# TokenEstimator 常数标定：实测值与推荐参数

> 时间：2026-11-13（UTC）。对象：`crates/llm-suite-token/src/estimation.rs` 的
> `TokenEstimator`（`cjk_factor` / `latin_factor` 与 `SYMBOL_FACTOR`）。
> 真值取样自 `BAAI/bge-m3` 的 `usage.prompt_tokens`；样本为第三方文档站与官方仓库的真实分块，
> 加四段长度可控的对照文本。本文只给测量值与推荐参数，不改动代码。

## 一、结论

现有常数（字母 0.25、标点 0.5、空白 0.5、中日韩 1.0）对英文散文高估 16%、对中文高估 18%、
对代码低估 16%、对 markdown 符号行低估 26%。推荐保留"按字符类别计权"的结构，
把标点从 0.5 提到 1.0、空白从 0.5 降到 0.2，字母与中日韩维持不动；改后四类对照样本的比值落在
0.91～1.18，真实文档与源码分块的总量比由 1.097 / 1.010 收到 1.076 / 0.996，
最差单项误差由 26% 收到 18%（方向为高估，对预算是安全侧）。

## 二、测量口径

- 真值：嵌入接口返回的 `usage.prompt_tokens`，一次只提交一段文本（批量接口只回聚合用量）。
- 对照样本：英文散文 848 字符、中文散文 296 字符、Python 片段 777 字符、markdown 符号行 304 字符。
- 真实分块：第三方文档 60 块（中位 542 字符）、官方仓库源码 60 块（中位 415 字符）；
  用于按类别做最小二乘，而不是只看整段对照。
- 复算方式：用同样的分类口径统计每段文本的"字母 / 标点 / 空白 / 中日韩 / 其他"字符数，
  再套用待评常数求令牌数，与真值相比。

## 三、实测数据

单位字符成本（真值，bge-m3）：

| 样本 | 字符 | 真令牌 | 令牌/字符 |
|---|---|---|---|
| 英文散文 | 848 | 214 | 0.252 |
| 中文散文 | 296 | 251 | 0.848 |
| Python 片段 | 777 | 315 | 0.405 |
| markdown 符号行 | 304 | 183 | 0.602 |

真实分块的估算/真值比：

| 语料 | 中位字符 | 中位真令牌 | 现有常数（总和比） | 推荐常数（总和比） |
|---|---|---|---|---|
| 英文文档（60 块） | 542 | 166 | 1.097 | 1.076 |
| Python 源码（60 块） | 415 | 148 | 1.010 | 0.996 |

四类对照样本在两个常数下的表现：

| 样本 | 真令牌 | 现有常数 | 比值 | 推荐常数 | 比值 |
|---|---|---|---|---|---|
| 英文散文 | 214 | 248 | 1.16 | 211 | 0.99 |
| 中文散文 | 251 | 296 | 1.18 | 296 | 1.18 |
| Python 片段 | 315 | 266 | 0.84 | 288 | 0.91 |
| markdown 符号行 | 183 | 136 | 0.74 | 189 | 1.03 |

按类别对 120 个真实块做最小二乘（汉字系数由纯中文样本固定）得到的等效系数：

```
字母 0.23   标点 1.00   空白 0.16   中日韩 0.85   其他 1.00
```

拟合质量：总量比 0.977、单块中位 0.949、p10 0.85 / p90 1.07；独立样本校验 0.91（英文）与 1.01（中文）。

## 四、推荐参数

```text
latin_factor = 0.25      # 保持
SYMBOL_FACTOR = 1.0      # 由 0.5 上调：bge-m3 下标点几乎逐字符计费
空白权重     = 0.2       # 由 0.5 下调：空格多与后词合并
cjk_factor   = 1.0       # 保持（实测 0.85，取 1.0 属安全侧高估）
其他 Unicode = 1.0       # 保持
```

说明：

- 标点系数没有做进 `TokenEstimator` 的可配置字段，仅是模块常量 `SYMBOL_FACTOR`；
  若希望按模型切换，建议与 `cjk_factor` / `latin_factor` 一并纳入结构体，
  保持"一个模型一套常数"的显式形态，而不是散成全局常量。
- 空白权重在 `estimate_with_config` 与 `find_split_point` 两处各有硬编码（0.5），
  需要同改，否则估算与切分对同一段文本给出不同结论。
- 现有单测的期望值会受影响，改常数时同步更新：`"fn foo() -> u32"` 由 6 变 7、
  `"Hello 世界"` 由 4 变 3、`"Hello   World"` 由 4 变 3；`"Hello World"`、`"你好，世界！"`、
  `"こんにちは世界"`、`"안녕하세요"` 不变。本次推荐常数下的期望值以此为准。

## 五、边界与后续

- 常数与分词器绑定：本次真值来自 bge-m3（XLM-R 系）。GPT/Claude 系的分词器空格自成一 token、
  部分标点合并，若这套估算要服务多家模型，应按 provider 维护常数表（结构体已支持自定义），
  并在每次接入新模型时重跑本文的取样流程。
- 中文实测为 0.85 令牌/字符，取 1.0 会稳定高估约 18%。作为预算上限是安全方向；
  若该估算用于**计费预估**（`metrics.rs` 的 `estimated_usage`），高估会让展示成本偏高，
  此时建议按 provider 区分：计费预估用拟合值，预算裁剪用上浮值。
- 本次没有覆盖：日文假名与韩文谚文的分项真值（样本里只有纯中文）、代码注释与非 ASCII 标识符、
  图像与工具声明的固定附加量（`estimate_message_tokens` 的 200/4 常量）。

## 六、复现

1. 取样：真实文档站与仓库分块各 60 条，加四段对照文本（长度 296～848 字符）。
2. 取真值：逐条请求嵌入接口，读 `usage.prompt_tokens`。
3. 比对：按本文的字符分类统计后套用待评常数；先由纯中文样本定 `cjk_factor`，
   再对字母/标点/空白做最小二乘。
4. 回写：常数、两处空白权重与单测期望值同批修改。
